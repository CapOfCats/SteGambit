# ADR 006: Протокол криптографической защиты и деривации ключей (Security KDF)

**Дата:** 2026-05-05
**Статус:** Утверждено
**Контекст:** Регламентация крипто-провайдера, алгоритма шифрования (AEAD) и процесса генерации ключей (KDF) на основе пароля пользователя.

## 1. Отказ от проприетарной криптографии
Во избежание уязвимостей (правило *Don't roll your own crypto*), проект использует исключительно стандартизированные примитивы. В качестве криптопровайдера утверждается библиотека `cryptography` (модули `hazmat`).

## 2. Утвержденные стандарты
*   **Симметричное шифрование:** `AES` в режиме `GCM` (Galois/Counter Mode). Длина ключа: **256 бит** (32 байта).
*   **Key Derivation Function (KDF):** `PBKDF2HMAC` с хеш-функцией `SHA-256`. Количество итераций: **480 тысяч!** (рекомендация NIST на текущий год).
*   **Соль (Salt):** **16 байт**, генерируется криптографически стойким генератором `os.urandom(16)` для каждой новой сессии скрытия.
*   **Вектор инициализации (Nonce/IV):** **12 байт**, генерируется через `os.urandom(12)`.

## 3. Модификация DTO Заголовка (Обновление ADR 004)
В связи с необходимостью хранения уникальной соли для KDF, бинарный формат DTO расширяется с 41 байта до **57 байт**.

**Новая структура фрейма (57 байт):**
| Поле | Размер (байт) | Назначение |
| :--- | :--- | :--- |
| `MAGIC`  | 4  | Сигнатура `SGB1` |
| `FLAGS`  | 1  | Битовая маска (Сжатие, Двойное дно) |
| `SALT`   | 16 | Соль для PBKDF2 (NEW) |
| `NONCE`  | 12 | Вектор инициализации AES-GCM |
| `LENGTH` | 8  | Размер исходного массива (int64) |
| `MAC`    | 16 | Authentication Tag |
| `DATA`   | N  | Шифротекст |

## 4. Пайплайн инкапсуляции (Embed Crypto Logic)
1. Сгенерировать рандомные `SALT` (16) и `NONCE` (12).
2. Вычислить `AES_KEY = PBKDF2(Password, SALT, iterations=480000)`.
3. Зашифровать данные (`Ciphertext, MAC = AES_GCM_Encrypt(AES_KEY, NONCE, Data)`).
4. Собрать 57-байтовый заголовок + `Ciphertext`.
5. Передать собранный массив байт в `SmartSpreader` и `LsbProcessor`.
