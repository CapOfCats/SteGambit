# Edge-detection Analysis для WAV (Подтаска #25.2)

**Дата прогона:** 2026-06-18 17:45:12

## 1. Цель

Проверить гипотезу из ТЗ #25:
> Для аудио (1D-массив WAV), edge-detection считает разность
> между соседними сэмплами. Порог `GRADIENT_THRESHOLD = 8` на
> шкале -32768..+32767 ничего не фильтрует -> почти все сэмплы
> попадают в пул, edge-detection становится no-op.

## 2. Методология

- **Платформа:** Windows-10-10.0.19045-SP0
- **Python:** 3.12.2
- **Итераций для замера времени:** 20
- **GRADIENT_THRESHOLD:** 8
- **Метрики:**
  - `pool_size / total` — какой процент позиций прошёл фильтр.
  - Если > 95% — фильтр практически не работает (гипотеза подтверждена).
  - Если < 50% — фильтр осмыслен.
  - Время `_build_edge_pool` — стоимость 'no-op' фильтрации.

## 5. Стоимость no-op (если гипотеза подтверждена)

Время `_build_edge_pool` для WAV показывает, сколько секунд
тратится на бессмысленную фильтрацию. Если оно небольшое
относительно полного hide_data (~260 ms для WAV), оптимизация
имеет малый приоритет.

## 6. Выводы

**Изначальная формулировка:** edge-detection для WAV — no-op, нужно
отключить или поднять порог.

**Реальные данные:**

| Условие | % в пуле | Edge-detection работает? |
|---|---|---|
| WAV белый шум (типичная музыка) | 99.97% | ❌ Нет |
| WAV тихая синусоида (тишина, медленные пассажи) | 84.99% | ⚠️ Слабо |
| PNG реальное фото | 15.15% | ✅ Да |
| PNG синтетический шум | 99.63% | ❌ Нет |

**Уточнение гипотезы:** edge-detection пропускает почти всё на любом
**высокоэнтропийном контенте** (шумные WAV И зашумлённые PNG).
На реальных фотографиях работает по назначению — отсев 85%.

### 6.2. Решение по WAV — не оптимизируем

**Аргументы против изменения:**

1. **Стоимость низкая.** `_build_edge_pool` для WAV = 7-8 ms из ~260 ms
   полного hide_data (3% overhead). Оптимизация даст экономию <10 ms.

2. **На тихих сигналах фильтр частично работает** (отсев 15%).
   Полное отключение ухудшит stealth-характеристики для тихой музыки.

3. **Адаптивный порог** = архитектурный рефакторинг, ломает обратную
   совместимость (старые стего-файлы не извлекутся — пул будет другим).

4. **Простое повышение порога** до 256 на шкале int16 не поможет:
   на белом шуме всё равно пройдёт ~100%, а на тихих сигналах
   отсечётся ВСЁ → сломаем capacity для тихих WAV.

**Решение:** edge-detection для WAV остаётся в текущем виде. Гипотеза
формально подтверждена для шумного контента, но рекомендация
"отключить" опровергнута анализом стоимости и edge-кейсов.
